# 设计文档：全项目注释通俗化改造（面向初学者）

日期：2026-08-20
状态：已获用户批准（风格示例 / 批次划分 / 保护约束 / 验证交付四节均通过）

## 背景与目标

用户是前端开发初学者 + AI agent 开发初学者，通过本仓库（12 个模块、约 16,000 行 TS、60+ 文件）自学 agent 模式。现状：

- 模块 11、12 已有深度中文注释（2026-08-19 提交）
- 模块 03–10 各文件有中文头部「学习目标」，但文件内部逐段解释深浅不一
- 模块 01（11 个子文件夹）部分有头部注释；模块 02 基本是裸代码

目标：把全项目注释升级为「初学者友好」版本——通俗、有例子、详细，同时不淹没代码本体。

## 用户已确认的决策

1. **覆盖顺序**：按模块顺序分批做，每批完成后暂停验收，批准后再继续下一批。
2. **现有注释**：改写升级（以现有中文注释为基底，通俗化 + 补例子；保留「学习目标/核心结论」头部结构）。用户明确授权改写现有学习笔记——这是对 CLAUDE.md「保留学习笔记」条款的显式例外，仅适用于本任务范围。
3. **举例形式**（用户选定两种）：
   - 🏠 生活化比喻（餐厅、工厂、新员工等日常类比）
   - 📤 具体输入输出走查（用真实数据演示 ①②③ 步骤流转）
   - （前端类比未选，不使用；⚠️ 易错点未选为主要形式，仅作偶尔的辅助标记，在确有高危易错点处少量使用）
4. **结构**：三层结构（文件头 / 段落级 / 关键行），非逐行注释。

## 注释风格规范

每个文件三层：

1. **文件头（约 15–25 行）**：`====` 包围块——章节名 → 🏠 比喻开场（一个主比喻贯穿全文件）→ 学习目标 → 核心结论。
2. **段落级（每个逻辑段前 3–10 行）**：这段在干什么、为什么需要、与其他段的关系。
3. **关键行**：只在真正难懂处（Zod schema、泛型、async 流程、agent loop 分支等）给 📤 输入→输出走查或 ⚠️ 易错点。

Emoji 标记约定（便于跳读）：🏠 比喻 / 📤 输入输出走查 / ⚠️ 易错点。比喻只在概念首次出现时展开，复用时一句话带过。

深度梯度：01 最细（含 TS 语法基础解释）→ 02/03 细 → 04–10 中（TS 语法注释递减，agent 概念保持）→ 11/12 轻量升级（补缺的比喻和走查、通俗化晦涩段落，不推倒重写）。

风格示例见本文末尾附录（以 02-tool-use 真实代码演示）。

## 硬性保护约束

- 代码逻辑一行不改——只增删改注释行和必要空行
- 保留所有被注释掉的代码，以及 `index_original.ts` / `index2.ts` 等刻意保留的文件
- 注释语言：中文（跟随仓库现有双语规则）
- README、`.env.example`、`package.json`、CI 配置一律不动
- 11/12 的测试逻辑不动（测试文件内的注释同样通俗化升级）

## 验证与交付流程（每批次）

1. typecheck：模块有 `typecheck` 脚本则 `npm run typecheck`，否则 `npx tsc --noEmit`；11/12 额外跑 `npm test`
2. `git diff` 自查：确认删掉的非注释代码行 ≈ 0（只允许注释行变动）
3. commit（消息风格：`优化 XX 注释：通俗比喻 + 输入输出走查`，短、单一关注点）
4. 暂停 → 用户抽查验收 → 意见修正或批准下一批

限制说明：01–10 的 `npm start` 需 OPENAI/TAVILY key 且真实调用模型，日常验证以 typecheck 为准；11/12 无需 key 可跑测试。
